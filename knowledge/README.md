# 知識庫

這裡放對話中整理出來的產業研究，內容包括論點、會讓論點失效的訊號、證據和推論。每次提問後由 Agent 更新。非買賣建議。

| 檔案 | 範圍 |
| --- | --- |
| [memory.md](memory.md) | 記憶體：2408 南亞科、2344 華邦電、8299 群聯 |
| [market-tw.md](market-tw.md) | 台股大盤：加權指數、0050、00631L |

## 和 pipeline 的分工

- **數字**（價格、P/B 檢視區、營收動能）由 pipeline 每日計算。知識庫只在有事件時引用快照，並附資料日期和執行紀錄連結。
- **論點文字**：`config/watchlist.yaml` 的 `rationale` 是報告網頁顯示的摘要，證據和出處以知識庫為準。兩邊不一致時，先改知識庫，再同步 `rationale`。

## 每份檔案的段落

1. **決策摘要**：最近一次深度更新的判斷，以及改變判斷的條件。
2. **論點**：一段話，寫明要追蹤的問題。
3. **失效條件與轉折訊號**：表格，欄位是訊號、檢查方式（pipeline 或人工）、目前狀態（附日期）。
4. **估值情境與排序**：依下方固定標準計算。
5. **數字快照**：只記有事件的日期。
6. **證據紀錄**：依事件分組，新的在上面。
7. **推論**：每則寫出依據哪幾則證據，以及什麼情況下推論不成立。
8. **更新紀錄**：每次深度更新改了哪些判斷、根據哪則新證據。
9. **待確認**

大盤檔案用「參考價位」取代「估值情境與排序」。參考價位的算法和 `docs/TECHNICAL_PRICE_CONTEXT.md` 相同，只用來描述，不是買賣價。

## 證據寫法

```text
- [影響｜誰說的｜查證] 內容（來源連結）
```

| 欄位 | 值 |
| --- | --- |
| 影響 | 支持、削弱、中性（對論點而言） |
| 誰說的 | 公司、交易所（證交所、櫃買中心的成交、法人、融資券資料，經 FinMind）、分析機構、媒體、分析師（法說會提問或投顧）、使用者筆記、pipeline |
| 查證 | **原文**：對照過逐字稿、公告、財報或官方資料<br>**轉述**：媒體或產業媒體報導，未對照原文<br>**未查到**：找不到出處 |

## 規則

- 使用者貼的筆記先記成「使用者筆記」，對照原文後才改成「公司」。#163 把筆記裡的「保守看緊到 2028」當成公司說法寫進 `rationale`，逐字稿裡沒有這句。
- 推論只寫在「推論」段落，不能當成證據引用，也不寫進 `rationale` 當出處。
- 缺值不補，寫「未查到」。
- 證據寫錯時不直接刪除：原句加刪除線，後面註明更正日期和原因。

## 固定標準

深度更新都照這些規則計算，前後兩次才比得出差異。要改標準時，在該檔案的「更新紀錄」寫明原因。

### 估值情境（12 個月）

價值 = 12 個月後的每股淨值 × P/B 倍數。股利視同留在淨值裡，算的是近似總報酬。

| 情境 | 未來 4 季 EPS 合計 | P/B 倍數 |
| --- | --- | --- |
| Bull | 最新一季 × 4 | 目前 PBR |
| Base | 最新一季 × 2 | 目前 PBR 和五年 P80 取較低者 |
| Bear | 0 | 五年 P50 |

- 每股淨值和 EPS 取最新一期財報（FinMind）。P/B 倍數 = pipeline 的檢視價 ÷（收盤價 ÷ PBR）。
- 報酬風險比 = Base 報酬 ÷ Bear 跌幅。
- 這套規則只適用以 P/B 估值的景氣循環產業，其他產業要另外訂。

### 投資吸引力

每項高 2 分、中 1 分、低 0 分，加總後排序。同分時，Bear 跌幅小的排前面。

| 項目 | 高 | 中 | 低 |
| --- | --- | --- | --- |
| 估值位置（P/B 五年百分位） | 低於 P40 | P40–P80 | 高於 P80 |
| 報酬風險比 | 大於 1 | 0.5–1 | 小於 0.5 |
| 財務韌性 | 淨現金為正，且近 2 季營業現金流都為正 | 只符合其中一項 | 都不符合 |
| 營收動能（近 3 個月單月月增率） | 都為正 | 1 個月為負 | 2 個月以上為負 |

### 研究優先級

符合一項得 1 分。同分時，Bear 跌幅大的排前面。

1. 30 天內有財報、法說會或月營收公布。
2. 這次更新有新的削弱證據，或 pipeline 狀態改變。
3. 和這檔有關的待確認項目有 2 項以上。

### 條件式判斷

- **避開**：符合任一項。
  - 單月營收月增率連續 2 個月為負。
  - 合約價由漲轉跌（TrendForce 或公司說法）。
  - 營業現金流連續 2 季為負，且存貨超過淨值的一半。
- **考慮買進**：沒有任何避開條件，且報酬風險比 ≥ 1。
  - 考慮買進價位：報酬風險比剛好等於 1 的股價。Base 的倍數用到「目前 PBR」時會跟著股價變動，所以每個試算股價都要重算 Base，不能直接用目前的 Base 價值。
  - 推導：設 g =（每股淨值 + 2 × 最新一季 EPS）÷ 每股淨值 − 1。股價低於 P80 檢視價時，Base 報酬固定等於 g，價位是 Bear 價值 ÷（1 − g）。股價高於 P80 檢視價時，Base 價值固定，價位是（Base 價值 + Bear 價值）÷ 2。兩段中，落在自己適用範圍內的那個才算數。
  - 2026-11-05 更正：原本只寫「（Base 價值 + Bear 價值）÷ 2」，沒有考慮 Base 會跟著股價變動。
- **觀望**：其他情況。
- 有持倉資料時：符合避開條件就考慮減碼，其他情況持有。

## 用法

找方向：

```text
找方向：<市場>，投資期間 12 個月。
找出產業趨勢或供應鏈瓶頸，最多 5 個候選。每個候選寫一句理由、
2–3 則可核對的證據（日期、來源、誰說的），以及最大的反面論點。不做估值。
```

深度更新：

```text
深度更新：<產業>
```

Agent 會以 `knowledge/<產業>.md` 作為前次結果，依序做以下幾件事：

1. 查核最新財報、月營收、現金流和負債。
2. 依固定標準計算估值情境、排序和條件式判斷。
3. 寫出最強的反面論點，以及可能造成永久損失的風險。
4. 更新失效條件，和下次要追蹤的事件。
5. 在「更新紀錄」寫下和前次比較的結果。

回覆時先給決策摘要，再更新檔案。
